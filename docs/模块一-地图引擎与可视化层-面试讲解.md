## 1. 模块概述

### 一句话定位

> 基于 MapLibre GL JS 构建车载地图渲染引擎，通过 Deck.gl 叠加 GPU 加速数据可视化层，实现海量 POI 渲染、图层控制、视口管理等能力，是整套导航系统的最底层视觉基础。

### 演示话术（背诵）

> "我们基于 MapLibre GL JS 构建了地图引擎，这是目前车载领域最主流的开源地图渲染引擎。它原生支持矢量瓦片，相比传统的栅格瓦片，矢量瓦片体积小 80%、支持动态样式切换、并且分辨率无关——在车机不同分辨率的屏幕上都能清晰显示。上层我们用 Deck.gl 做数据可视化，通过 MapboxOverlay 让两者共享同一个 WebGL 上下文，实现相机完全同步。"

### 功能清单总览

| 功能 | 优先级 | 技术 | 状态 |
|------|--------|------|------|
| 底图加载 + 样式切换 | P0 | MapLibre Style | ✅ |
| 地图控制 | P0 | MapLibre 内置交互 | ✅ |
| 图层控制 | P0 | setLayoutProperty / setPaintProperty | ✅ |
| 视口管理 | P0 | Zustand + map 'move' 事件 | ✅ |
| 数据驱动样式 | P0 | MapLibre Expressions | ✅ |
| 3D 建筑 | P1 | fill-extrusion | ✅ |
| Deck.gl 同步 | P0 | MapboxOverlay | ✅ |

## 2. 技术选型与理由

### 2.1 MapLibre GL JS vs Cesium

| 维度 | MapLibre | Cesium |
|------|----------|--------|
| 定位 | 2.5D 矢量地图引擎 | 3D 地球引擎 |
| 擅长 | 道路网络、样式定制、导航场景 | 全球尺度三维可视化 |
| 瓦片 | 矢量瓦片（原生支持） | 3D Tiles / 栅格 |
| 车载适用性 | ✅ 主流 | ❌ 偏重 |

**面试话术**：车载导航场景道路清晰、样式可控、性能优先，MapLibre 更合适。Cesium 做全球三维、倾斜摄影、3D Tiles 更在行。

### 2.2 矢量瓦片 vs 栅格瓦片

| 维度 | 矢量瓦片 | 栅格瓦片 |
|------|---------|---------|
| 体积 | 小 60-80% | 大 |
| 样式切换 | 客户端渲染，即时切换 | 需重新下载 |
| 分辨率无关 | ✅ 车机不同 DPI 清晰 | ❌ 放大模糊 |
| 交互查询 | ✅ 可点击获取属性 | ❌ 只是图片 |

**面试话术**：我们底图用了 CartoDB 栅格瓦片（快速起步），同时叠加天地图标注。如果要体现"矢量瓦片优势"，重点讲：样式切换不用重新下载、分辨率无关、可交互查询属性。项目中 `tippecanoe` 自建瓦片链路是加分项。

### 2.3 天地图 + CartoDB 双底图

- **CartoDB**：白天/夜间样式切换，全球底图
- **天地图**：中文标注（国内合规，符合国家测绘规定）

**面试加分点**：提到"车载产品在国内必须用合规地图数据源（天地图/高德/百度），这是产品落地的前置条件"，体现工程经验。

### 2.4 Zustand 状态管理

选择理由：
- 轻量（~1KB）
- 无 Provider 包裹，hooks 直接使用
- 支持非组件环境调用 `getState()`（事件回调里用）

## 3. 整体架构设计

### 3.1 架构分层

```
┌─────────────────────────────────────────────┐
│  LayerPanel (纯 UI 组件)                      │
│  - 只接收 props, 不碰地图                      │
└──────────────────┬──────────────────────────┘
                   │ onToggle / onSetOpacity (回调)
┌──────────────────▼──────────────────────────┐
│  MapView (组件编排)                           │
│  - 持有 layerStates (React state)            │
│  - 包装回调: 先操作地图, 再更新 UI 状态        │
└──────────────────┬──────────────────────────┘
                   │ 调用 hook
┌──────────────────▼──────────────────────────┐
│  useMapInit (自定义 Hook)                     │
│  - 创建 MapLibre 实例                         │
│  - 添加原生图层 + Deck.gl 图层                 │
│  - 监听 move 事件 → 更新视口 store             │
└──────────────────┬──────────────────────────┘
                   │ 写入
┌──────────────────▼──────────────────────────┐
│  mapStore (Zustand)                          │
│  - viewport: 视口信息 (供其他模块读取)          │
│  - mapReady: 地图加载状态                      │
└─────────────────────────────────────────────┘
```

### 3.2 关键设计原则

1. **组件解耦**：LayerPanel 是纯展示组件，不 import 地图，只通过 props 和回调通信
2. **Hook 封装副作用**：所有地图副作用（创建实例、事件监听、图层添加）集中在 `useMapInit`
3. **Store 共享状态**：视口信息放 Zustand，供模块三（充电站查询）、模块五（R-Tree 过滤）复用
4. **双向状态同步**：`map.getLayoutProperty`（读真实状态）→ React state（UI 展示）→ `map.setLayoutProperty`（写回地图）

### 3.3 为什么用 forwardRef + useImperativeHandle

父组件（Layout）需要控制地图（飞行、切换主题），所以 MapView 通过 ref 暴露：

```typescript
export interface MapliberHandle {
  flyTo: (lng, lat, zoom?) => void;   // 飞到坐标
  getMap: () => Map | null;           // 获取地图实例
  toggleDark: (val) => void;          // 切换主题
}
```

- `forwardRef`：让 ref 可以穿透到 MapView 内部
- `useImperativeHandle`：**只暴露指定的方法**，不暴露整个组件实例（更安全，防止父组件乱操作内部状态）

## 4. 核心功能详解

### 4.1 底图加载与样式切换

**代码位置**：`src/config/mapStyle.ts`

```typescript
export function getMapStyle(isDarkMode: boolean): StyleSpecification {
  const baseLayerUrl = isDarkMode
    ? 'https://basemaps.cartocdn.com/dark_all/{z}/{x}/{y}@2x.png'   // 夜间
    : 'https://basemaps.cartocdn.com/light_all/{z}/{x}/{y}@2x.png'; // 白天

  return {
    version: 8,           // Style Spec 版本
    sources: {
      cartodb_base: { type: 'raster', tiles: [baseLayerUrl], tileSize: 256 },
      tianditu_labels: { type: 'raster', tiles: [天地图 WMTS], tileSize: 256 },
    },
    layers: [
      { id: 'cartodb_layer', type: 'raster', source: 'cartodb_base' },
      { id: 'tianditu_labels_layer', type: 'raster', source: 'tianditu_labels' },
    ],
  };
}
```

**核心知识点**：

1. **Style Spec v8**：MapLibre 的样式规范，`sources` 定义数据源，`layers` 定义如何渲染
2. **瓦片 URL 模板**：`{z}/{x}/{y}` 是占位符，MapLibre 按当前缩放/位置自动请求对应瓦片
3. **栅格 vs 矢量 source**：这里用的 `type: 'raster'`（PNG 图片），矢量瓦片是 `type: 'vector'` + PBF

**切换样式**：

```typescript
const toggleDark = (val: string) => {
  map.setStyle(getMapStyle(val === 'dark'));  // 整个替换 Style 对象
};
```

⚠️ **面试注意点**：`setStyle()` 会**清空所有自定义图层**（路网、点、Deck.gl 层都会消失）。所以切换主题后需要在 `map.on('load')` 里重新添加。这是一个真实的坑，面试提出来很加分。

### 4.2 图层控制面板

**代码位置**：`src/components/LayerPanel/index.tsx`

**功能**：每个图层有显隐切换（✓/○ 按钮）+ 透明度滑块。

**核心 API**：

```typescript
// 显隐: layout 属性
map.setLayoutProperty(layerId, 'visibility', 'visible' | 'none');

// 透明度: paint 属性 (不同图层类型属性名不同)
map.setPaintProperty(layerId, 'line-opacity', 0.5);
map.setPaintProperty(layerId, 'raster-opacity', 0.5);
map.setPaintProperty(layerId, 'fill-opacity', 0.5);
map.setPaintProperty(layerId, 'fill-extrusion-opacity', 0.5);
```

**LAYER_CONFIG 配置驱动**：

```typescript
const LAYER_CONFIG = [
  { id: 'road-major', name: '主干道', group: '路网', opacityProp: 'line-opacity' },
  { id: 'big-data-scatter', name: '海量数据点', group: 'Deck.gl', opacityProp: '' },
  // opacityProp 为空 = Deck.gl 图层, 不显示透明度滑块
];
```

**设计亮点**：用一份配置表驱动面板渲染 + 图层操作，新增图层只需加一行配置，不用改 UI 代码。

### 4.3 数据驱动样式（MapLibre Expressions）

**代码位置**：`src/layers/createMapLayers.ts`

```typescript
paint: {
  'line-color': [
    'match',
    ['get', 'class'],        // 取道路的 class 属性
    'motorway',  '#FF6B35',  // 高速 → 橙
    'primary',   '#FFB347',  // 主干 → 黄
    'secondary', '#FFD700',  // 次干 → 金
    '#CCCCCC',               // 默认 → 灰
  ],
  'line-width': [
    'interpolate', ['linear'], ['zoom'],  // 随缩放插值
    10, 2,   // zoom 10 时 2px
    15, 8,   // zoom 15 时 8px
    18, 15,  // zoom 18 时 15px
  ],
}
```

**面试话术**（背诵）：
> "MapLibre 的 Expressions 系统非常强大，允许我们用类似 SQL 的表达式做数据驱动渲染。比如道路宽度随缩放级别动态插值，充电站颜色根据空闲/占用状态实时变化。所有计算在 GPU 端完成，几乎没有性能开销。"

**为什么是 `['get', 'class']` 而不是 `d.class`？**
- MapLibre 图层的数据来自 source（矢量瓦片/GeoJSON），是"地图要素"，不是 JS 对象
- 用表达式 `['get', 'class']` 在**渲染时**从要素属性取 `class` 字段
- 这跟 React 里 `data.map(d => d.class)` 完全不同——MapLibre 的表达式系统是声明式的、GPU 友好的

### 4.4 视口管理

**代码位置**：`src/hooks/useViewport.ts` + `src/store/mapStore.ts` + `src/types/map.ts`

**类型定义**：

```typescript
export type BBox = [number, number, number, number];  // [west, south, east, north]

export interface Viewport {
  center: [number, number];  // [lng, lat]
  zoom: number;
  pitch: number;
  bearing: number;
  bounds: BBox;
}
```

**实现原理**：

```typescript
// useMapInit 里
const syncViewport = () => {
  useMapStore.getState().updateViewport(extractViewport(map));
};
map.on('move', syncViewport);  // 地图移动 → 更新 store
```

**为什么用 `getState()` 而不是 `useMapStore()`？**
- 这是在**事件回调**里（非 React 组件渲染阶段）
- `useMapStore()` 是 React Hook，只能在组件顶层调用
- Zustand 的 `getState()` 是纯函数，任何地方都能用

**BBox 为什么是 `[west, south, east, north]`？**
- GIS 标准：西南角 + 东北角
- west < east、south < north 恒成立 → 空间索引比较大小即可判断相交
- 地图旋转时，BBox 仍是"包含全部可见区域的最外层矩形"

**后续模块怎么用**：
```typescript
// 模块三: 查视口内充电站
const viewport = useViewport();
await chargingService.fetchStations(viewport.bounds, viewport.zoom);

// 模块五: R-Tree 按视口过滤
const visibleStations = rTree.search(viewport.bounds);
```

### 4.5 Deck.gl 集成（MapboxOverlay）

**代码位置**：`src/layers/createDeckLayer.ts`

**核心：MapboxOverlay 让两套渲染引擎共享 GL 上下文**

```typescript
const overlay = new MapboxOverlay({
  layers: [lineLayer, scatterLayer],
});
map.addControl(overlay);  // 作为控件挂到地图上
```

**为什么用 MapboxOverlay 而不是 `<DeckGL>` React 组件？**

| 方案 | 相机同步 | 渲染层级 | 复杂度 |
|------|---------|---------|--------|
| `<DeckGL viewState={...}>` | 需手动监听 move 同步 | 独立 canvas，需 pointer-events:none | 高 |
| **MapboxOverlay** | **自动同步**（共享 GL 上下文） | 画进同一 canvas | 低 |

**面试话术**：
> "最初我们用了独立的 DeckGL React 组件，需要手动监听地图 move 事件同步 viewState，还有两个 canvas 叠加的层级问题。后来改成 MapboxOverlay——它让 deck.gl 直接画进 MapLibre 的 GL 上下文，相机完全自动同步，代码量大幅减少。"

**ScatterplotLayer 的 GPU 优化**：

```typescript
new ScatterplotLayer({
  data: 50000个点,
  _instanced: true,  // 🔑 GPU 实例化渲染
  getPosition: (d) => [d.longitude, d.latitude],
  getFillColor: (d) => [v*255, (1-v)*255, 60, 180],  // 数据驱动颜色
});
```

**`_instanced: true` 是什么？**
- 传统画 5 万个圆 = 5 万次 draw call（CPU 逐个提交）
- 实例化渲染 = **1 次 draw call**，把 5 万个顶点的位置/颜色打包成一个 buffer 一次提交 GPU
- GPU 并行处理所有顶点，CPU 解放 → 5 万点 60fps

**`_` 前缀是私有 API**：deck.gl 里下划线开头的属性是内部 API，用 `as any` 绕过类型检查（这是真实的工程处理方式）。

### 4.6 图层显隐：MapLibre vs Deck.gl 两套体系

```typescript
// useMapInit 里的 toggleVisibility
const toggleVisibility = (layerId) => {
  // MapLibre 原生图层
  if (map.getLayer(layerId)) {
    map.setLayoutProperty(layerId, 'visibility', newVis);
  }
  // Deck.gl 图层
  else if (deckLayersRef.current.some(l => l.id === layerId)) {
    const updated = deckLayersRef.current.map(l =>
      l.id === layerId ? l.clone({ visible }) : l  // clone 新实例
    );
    overlay.setProps({ layers: updated });  // 整批刷新
  }
};
```

**面试重点**：
- MapLibre 和 Deck.gl 是**两套独立的图层系统**
- MapLibre 用 `setLayoutProperty`（原地修改，GPU 友好）
- Deck.gl 的图层是**不可变（immutable）的**，改属性必须 `clone()` 新实例再 `setProps()`
- 判断方式：`map.getLayer(id)` 返回 null 说明它是 deck.gl 的图层

## 5. 关键技术点深度解析

### 5.1 React 生命周期与地图初始化的配合

```typescript
useEffect(() => {
  // 1. 创建地图
  const map = new MapLibreMap({...});
  mapRef.current = map;

  // 2. 监听事件
  map.on('load', () => { /* 添加图层 */ });
  map.on('click', handleClick);

  // 3. 清理函数 (组件卸载时执行)
  return () => {
    map.remove();  // 🔑 销毁地图, 释放 WebGL 资源
    mapRef.current = null;
  };
}, []);  // 空依赖: 只在挂载时执行一次
```

**关键点**：
- `[]` 空依赖防止重复创建地图
- `map.remove()` 必须调用，否则多次挂载/卸载会内存泄漏
- `mapRef.current = null` 让引用失效

### 5.2 图层状态的双向同步

```
① 初始化: map.getLayoutProperty() → React state (真实状态 → UI)
② 用户点击: 回调 → map.setLayoutProperty() + setState (UI → 地图)
```

**为什么初始化要读真实状态？**
- MapLibre 是"真相源"，React state 只是 UI 的影子
- 如果直接用假初始值，面板第一次打开会显示错误状态

### 5.3 天地图 WMTS 接口

```
https://t0.tianditu.gov.cn/vec_w/wmts?...&TILEMATRIX={z}&TILEROW={y}&TILECOL={x}&tk=你的KEY
```

- **WMTS**：Web Map Tile Service，OGC 标准瓦片接口
- `{z}/{y}/{x}` 和 MapLibre 的 `{z}/{x}/{y}` 对应（注意 y 轴翻转）
- `tk=` 是天地图申请的 API Key

### 5.4 3D 建筑（fill-extrusion）

```typescript
paint: {
  'fill-extrusion-color': '#ff66cc',
  'fill-extrusion-height': ['get', 'height'],  // 从属性取高度
  'fill-extrusion-opacity': 0.8,
}
```

- `fill-extrusion` 是 MapLibre 原生 3D 渲染类型，在 2D 地图上拉伸成 3D 块
- 高度从要素属性 `height` 动态读取（又是数据驱动）
- 配合 `pitch: 45` 俯仰角才能看到 3D 效果

## 7. 面试高频问答

### 基础篇

**Q1: 为什么用 MapLibre 而不是 Cesium？**
> 见 2.1。补充：车载导航是 2D/2.5D 场景为主，MapLibre 的矢量瓦片 + 样式定制更适合。Cesium 太重，适合全球三维。

**Q2: 矢量瓦片和栅格瓦片区别？**
> 见 2.2。核心：体积、样式切换、分辨率、交互。

**Q3: 底图用了哪些数据源？为什么选天地图？**
> CartoDB（白天/夜间）+ 天地图（中文标注）。天地图是国产合规数据，车载产品落地必须用国内合规源。

**Q4: MapLibre 和 Deck.gl 怎么协作的？**
> 通过 MapboxOverlay 共享 WebGL 上下文。MapLibre 管底图和交互，Deck.gl 管大数据可视化层，相机自动同步。

### 进阶篇

**Q5: setStyle 切换主题后图层为什么消失了？怎么解决？**
> `setStyle` 会重置整个 Style 对象，自定义图层（addLayer 加的）全没了。解决：在 `map.on('load')` 回调里统一重新添加所有图层（我们的代码就是这么组织的）。

**Q6: MapLibre Expressions 和 JS 函数有什么区别？**
> Expressions 是声明式的、可在 GPU 端执行的表达式树，用 `['get', 'class']` 从要素属性取值。JS 函数是在 CPU 端逐要素执行。大数据量下 Expressions 性能更好。

**Q7: 5 万点怎么做到 60fps？**
> 三层优化：① `_instanced: true` GPU 实例化，5 万点 1 次 draw call；② 数据打包成 buffer 一次性上传 GPU；③ CPU 端只传数据数组，渲染完全在 GPU。

**Q8: MapLibre 图层和 Deck.gl 图层怎么统一控制显隐？**
> 两套体系。MapLibre 用 `setLayoutProperty`；Deck.gl 图层不可变，`clone()` 新实例 + `setProps()`。用 `map.getLayer(id)` 判断属于哪套。

**Q9: 视口 BBox 怎么获取？为什么是 [west, south, east, north]？**
> `map.getBounds()` 拿 SW/NE 两个角。顺序保证 west<east, south<north 恒成立，空间索引判断相交只需比较大小。

**Q10: Zustand 的 getState() 和 useStore() 区别？**
> `useStore()` 是 React Hook，订阅变化触发重渲染，只能在组件顶层。`getState()` 是普通函数，任何地方可调用，适合事件回调里读状态。

**Q11: forwardRef + useImperativeHandle 干什么用？**
> forwardRef 让 ref 穿透组件边界；useImperativeHandle 只暴露指定方法（flyTo/getMap/toggleDark），避免父组件拿到整个实例乱操作。

### 深挖篇（杀手锏）

**Q12: 你项目里 MapLibre 和 React 的状态是怎么同步的？**
> 分层：React state 管 UI（layerStates），MapLibre 是"真相源"。初始化时用 `getLayoutProperty` 读真实状态填 UI；操作时回调里 `setLayoutProperty` 写地图 + `setState` 更新 UI。

**Q13: 为什么 Deck.gl 图层要 clone 而不是直接改？**
> deck.gl 图层是 immutable 的，内部通过 diff 新老 layer 实例来判断是否需要重建。`clone(newProps)` 生成新实例，deck.gl 对比 props 决定更新策略。

**Q14: 地图组件卸载时要注意什么？**
> ① `map.remove()` 释放 WebGL 上下文和 GL 资源；② 移除事件监听（click/move）；③ ref 置 null；④ 用 `[]` 依赖保证只初始化一次。

**Q15: 如果让你优化这个模块的性能，你会怎么做？**
> ① 底图换成矢量瓦片（tippecanoe 自建）减少流量；② 图层面板改成防抖更新，避免滑块拖动时频繁 setPaintProperty；③ 海量点用 R-Tree 空间索引按视口过滤（模块五）；④ 图层懒加载，按需 addLayer。
